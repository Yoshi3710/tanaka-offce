# 変更・公開前の検証基準と結果記録

最新版の仕様は [CURRENT_SPEC.md](./CURRENT_SPEC.md) にあります。Xserverへ本番移行した後も継続適用します。

## 1. 変更時の手順

1. 対象ファイルの最新内容・GitHub SHA・現在の公開画面・現在の機能を確認する。別チャットや別ファイルを参照する場合、元データを実際に読む。
2. 変更対象と「変更してはいけない場所」を明確化し、変更範囲を限定する。
3. 構文・機能・表示・保存・印刷に影響するかを評価。影響が避けられないときは事前相談。
4. 修正・検査。**変更前後の差分**と未使用・重複コード、外部通信を確認する。
5. node tests/verify.cjs を実行。GitHub Actionsの自動検証結果も確認する。
6. **PC・スマホ実画面**と印刷プレビューを確認してはじめて表示の合格を宣言する。自動検査では代替できない。
7. 公開後にPagesの反映状態と変更内容を再確認。本番Xserverの場合は事前承認と復旧計画を必須とする。
8. 変更箇所・維持した機能・軽量化・実施した検証・未確認事項・残存リスクを簡潔に報告する。

## 2. 具体的な受入チェック

| 区分 | 検査内容 | 自動／実機 |
|---|---|---|
| 仕様 | 帳票4種類／担当営業6名の正式な表記／最新の文言と配置 | 両方 |
| 明細 | **[object Object]**等の表示がない／5行初期表示／商品追加・削除／数値入力／金額・税計算／不正数値の警告 | 両方 |
| 書式 | **全項目が枠内に収まる**。日付は1行、長文欄は必要に応じて高さ拡張。表記の折返しや余計な線がない | **実機必須** |
| 発注書 | A4縦・帳票へ直接入力・明細縦中央／指定の横揃え／納品先情報・メーカー情報 | 両方 |
| 見積書 | 発注書に近い操作、発売元・見積番号・学校名・単価／金額／見積有効期限・税込合計 | 両方 |
| 帳票切替 | 発注書・見積書・納品書・請求書を切替しても元データが消えない／他帳票の表示に影響しない | 両方 |
| 保存・復元 | JSON保存・読み込み／旧版データ互換／初期化確認／不正ファイルの拒否 | 両方 |
| 印刷 | **入力パネル・説明・操作部は印刷されず帳票本体だけ**。A4縦、余白、改ページ、PDF保存、日本語表示 | **実機必須** |
| PC | Windows Chrome／Edgeでの入力・帳票切替・保存・印刷・横スクロール | **実機必須** |
| スマホ | iPhone Safari／Android Chromeで文字の欠け・横スクロール・タッチ入力・画面切替 | **実機必須** |
| アクセシビリティ | ラベル、フォーカス、キーボード操作、縮小時の読みやすさ | 両方 |
| 安全 | 外部への入力データ無断送信なし／実データを公開試作に置かない／本番の認証・権限・CSRF・入力検証 | 自動＋運用確認 |
| 本番復元 | DBと書類のバックアップ／復元テスト／二重注文防止／誤操作回復 | **Xserverステージングで必須** |

**検証済みと未確認は必ず区別する。** GitHub ActionsのSuccessはコード上のチェック合格を意味し、Windows・スマホ・紙出力の実機合格を意味しない。

## 3. 不具合と改善提案の記録様式

| 日付 | 対象／版 | 現象・再現手順 | 影響 | 根本原因 | 対処案 | 変更範囲 | 検証 | 承認 |
|---|---|---|---|---|---|---|---|---|
| 記入 | 記入 | 記入 | 重大／中／低 | 分かる範囲で記入 | 暫定策と根本対策を区別 | 具体的に記入 | 済／未確認 | 済／保留 |

過去に発生した再発防止の重点：
- 発注書と見積書で別々の入力方式を使い、操作と見た目が一致しなかった。
- 配列の引数順の誤りで **[object Object]** が表示された。
- 上書きCSSの競合で印刷時に編集欄が混入した。
- 日付・長いラベルが枠外にはみ出した。
- 旧READMEに「太田」「発注書A4横」等の古い仕様が残った。
